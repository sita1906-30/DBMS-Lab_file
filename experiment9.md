### 3. Query Execution Before Indexing

Three queries were executed before creating indexes.

**Query 1: Search by Train Number**

```sql
SELECT *
FROM Railway_Booking
WHERE train_no = 12025;
```

**Query 2: Search by Source Station and Journey Date**

```sql
SELECT *
FROM Railway_Booking
WHERE source_station = 'Delhi'
AND journey_date = '2026-02-15';
```

**Query 3: Search by Train Number, Journey Date and Booking Status**

```sql
SELECT *
FROM Railway_Booking
WHERE train_no = 12025
AND journey_date = '2026-02-15'
AND booking_status = 'Confirmed';
```

**Sample Query Results:**

| Query | Matching Records |
|---|---:|
| Query 1 | 50 |
| Query 2 | 14 |
| Query 3 | 1 |

### 4. Single-Column Index Creation

The following indexes were created:

```sql
CREATE INDEX idx_train_no
ON Railway_Booking(train_no);

CREATE INDEX idx_source_station
ON Railway_Booking(source_station);

CREATE INDEX idx_journey_date
ON Railway_Booking(journey_date);
```

The `ANALYZE TABLE` command was executed to refresh optimizer statistics.

```sql
ANALYZE TABLE Railway_Booking;
```

**Result:** Single-column indexes were successfully created on train number, source station and journey date.

### 5. Query Execution After Single-Column Indexing

The same three queries were executed again using the single-column indexes.

**Result:** The database optimizer could use available indexes to improve data retrieval. The actual execution plan depends on the MySQL optimizer and table statistics.

### 6. Composite Index Creation

The following composite indexes were created:

```sql
CREATE INDEX idx_source_date
ON Railway_Booking(source_station, journey_date);

CREATE INDEX idx_train_date_status
ON Railway_Booking(train_no, journey_date, booking_status);
```

The optimizer statistics were refreshed:

```sql
ANALYZE TABLE Railway_Booking;
```

**Result:** Composite indexes were successfully created for queries involving multiple search conditions.

### 7. Query Execution After Composite Indexing

The three queries were executed again using the composite indexes.

| Query | Index Used/Available |
|---|---|
| Query 1: Train number | idx_train_no |
| Query 2: Source station and journey date | idx_source_date |
| Query 3: Train number, date and status | idx_train_date_status |

**Result:** Composite indexes provide a suitable access path for queries that filter on the indexed columns in the specified order.

The experiment successfully demonstrated the creation of a Railway Booking table containing 5,000 records. Single-column and composite indexes were created and tested using different SQL queries.
